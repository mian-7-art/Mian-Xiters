## Core Components

- **`EspLib/EspOverlayWindow.xaml` / `EspOverlayWindow.xaml.cs`**: Transparent, click-through, top-most WPF overlay rendering real-time bounding boxes, skeletal lines, health bars, and distance text.

### 2. Memory Engine & Scanner
- **`mozih4x.cs`**: Low-level memory management (`ReadProcessMemory`, `WriteProcessMemory`, `VirtualQueryEx`, `VirtualProtectEx`, `AoBScanSync`, `AobReplace`).

### 3. Emulation Memory System (`EspLib/`)

### 4. Application Protection & Security

## Data Flow

1. **Initialization:** `Program.cs` launches `SecurityGuard` checks -> initializes WPF `App` -> loads `MainWindow`.
2. **Process Attachment:** User selects action -> `GetProcess` enumerates running emulators sorted by RAM footprint -> attaches via `mozih4x.cs` / `EspLib`.
3. **Scan & Read:** `AoBScanSync` scans memory ranges for pattern signatures -> populates entity structures and offsets.
4. **Render:** `EspManager` reads target entity matrices continuously -> converts 3D world coordinates to 2D screen space (`EspW2S.cs`) -> draws primitives on `EspOverlayWindow`.

## Technical Debt & Considerations

- **64-Bit Memory Overflow:** Historical reliance on signed `long` instead of `ulong` for high memory address bounds checking (`> 0x8000000000000000`).
- **P/Invoke Alignment:** `MEMORY_BASIC_INFORMATION` structures must maintain strict alignment for both x86 and x64 WOW64 processes.
- **Thread Synchronization:** High-frequency rendering loops must ensure smooth UI thread execution without locking WPF looper threads.
